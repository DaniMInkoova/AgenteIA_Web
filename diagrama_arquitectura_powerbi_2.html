Sistema de consulta en lenguaje natural sobre Power BI

Capa de consulta que permite a empleados autorizados preguntar en lenguaje natural sobre los modelos semánticos de Power BI, sin conocer DAX. Los informes actuales permanecen intactos.

Escenario A · Premium Per User (arquitectura actual) Power BI: cuenta de servicio · OAuth 2.0 / MSAL Solo lectura Acceso web: solo VPN · sin autenticación de usuario (por ahora) Servidor local · 10.81.2.179

1 Arquitectura de componentes

Todos los componentes que manejan credenciales o datos residen en infraestructura de la organización (verde), sobre un servidor local (10.81.2.179). El servicio de IA (ámbar) actúa solo como motor de interpretación: no tiene credenciales, no accede a bases de datos y no mantiene estado entre peticiones. Actualmente el acceso a la aplicación web se realiza solo a través de la VPN corporativa, sin autenticación de usuario; los componentes de Microsoft Entra ID y de auditoría quedan reservados para una fase futura.

2 Flujo detallado de una consulta

Recorrido de una pregunta desde que el usuario la escribe hasta que recibe la respuesta verificable. Los pasos 4 a 8 forman un ciclo controlado, limitado a un máximo de 4–6 iteraciones.

1

Acceso a la aplicación

UsuarioVPN corporativaFrontend

Por ahora no hay autenticación de usuario. El acceso a la web se controla exigiendo conexión a la VPN corporativa: solo quien está dentro de la red corporativa puede alcanzar la aplicación. La autenticación con SSO de Microsoft Entra ID y la verificación por grupo de seguridad quedan reservadas para una fase futura.

2

Envío de la pregunta

FrontendBackend

El frontend envía al backend la pregunta en lenguaje natural, el identificador de conversación y el token de sesión. El navegador nunca tiene credenciales de Power BI ni la clave del servicio de IA.

3

Validación y preparación en el backend

Backend FastAPI

Valida el token y la pertenencia al grupo, recupera el historial de la conversación, comprueba los límites de uso y compone la petición con el contexto del modelo (tablas, columnas, medidas, relaciones y reglas), transmitido mediante prompt caching.

4

↻ Ciclo controlado · pasos 4–8 · máx. 4–6 iteraciones

Interpretación por el modelo

BackendAPI Anthropic (Claude)

El modelo recibe la pregunta y el esquema, y devuelve una solicitud de herramienta: descubrimiento (metadatos adicionales) o ejecución (una consulta DAX concreta). El DAX lo genera el modelo; no está predefinido en la aplicación.

5

Validación de la consulta

Servidor MCP

Antes de ejecutar nada, el MCP verifica que la consulta es de solo lectura, que el modelo destino está autorizado, y comprueba los límites de resultado y el tiempo máximo. Si no supera las validaciones, se rechaza sin llegar a Power BI.

6

Ejecución contra Power BI

Servidor MCPPower BI

El MCP obtiene un token válido (cuenta de servicio PPU · OAuth 2.0 / MSAL) y ejecuta el DAX vía la API REST de Power BI. Si el modelo es DirectQuery, la ejecución desciende por la puerta de enlace hasta el origen. El resultado vuelve en formato tabular.

7

Limitación del resultado

Servidor MCP

Antes de devolver los datos: truncamiento de filas al límite configurado, marca explícita de truncamiento (para que el modelo reformule agregando) y eliminación de columnas excluidas por configuración.

8

Iteración controlada

ClaudeBackend

Con el resultado, el modelo puede redactar la respuesta final, corregir y reejecutar la consulta, o lanzar una consulta complementaria. Al alcanzar el límite de iteraciones, se devuelve la mejor respuesta disponible con una advertencia explícita.

9

Entrega de la respuesta

BackendFrontend

El backend devuelve al frontend la respuesta en lenguaje natural, la tabla de datos y la consulta DAX ejecutada, que se muestra siempre para permitir la verificación independiente. El registro y la auditoría en SQL Server (pregunta, DAX, filas, tokens y latencia) quedan reservados para una fase futura.

Estado actual. El servidor que aloja el backend y el servidor MCP es una máquina local (10.81.2.179), no una VM de Azure. El acceso a la aplicación web se protege únicamente mediante la VPN corporativa, sin autenticación de usuario. Microsoft Entra ID (SSO) y el registro/auditoría en SQL Server están contemplados en el diseño pero no se usan por el momento; se dejan preparados para una fase futura. El servidor es una máquina virtual sobre VMware con Ubuntu 24.04 LTS, 8 vCPU (Intel Xeon Gold 5218R), 32 GB de RAM y 200 GB de disco.

Nota sobre el escenario. Estos diagramas reflejan el Escenario A — Premium Per User, la arquitectura actual del documento: la autenticación contra Power BI se realiza mediante una cuenta de servicio dedicada con licencia PPU (flujo delegado OAuth 2.0 con MSAL) y exclusión de MFA con controles compensatorios. El mecanismo de autenticación es una decisión abierta (sección 12): en el Escenario B — capacidad Fabric se sustituiría por una entidad de servicio con certificado, eliminando la cuenta de servicio y la exclusión de MFA.
